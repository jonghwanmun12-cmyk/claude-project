# 13 — 일자별 일정에 후보 리스트 + Day별 이미지

## Outcome

일자별 일정의 각 Day 카드에 그 도시의 관광지·맛집 후보 리스트(구글맵 링크 포함)와 이미지 4~5장이 함께 표시된다.

## Blockers

12-nearby-places-candidates — 같은 관광지·맛집 후보 데이터를 재사용해 중복 큐레이션을 피한다.

## Acceptance criteria

- [ ] 일자별 일정의 각 Day 카드에 그 날 머무는 도시의 관광지·맛집 후보가 리스트로 표시되고, 각 후보에 구글맵 링크 버튼이 있다.
- [ ] 각 Day 카드에 그 도시 이미지가 4~5장 표시된다. 큐레이션된 이미지가 4~5장보다 적은 도시는 있는 만큼만 표시된다(빈 자리를 억지로 채우지 않는다).
- [ ] 같은 도시에 머무는 여러 Day(예: Day 2, Day 3 모두 로마)는 각각 카드가 있으며 같은 도시 데이터를 일관되게 보여준다.
- [ ] 이미지가 깨지면 그 이미지 자리에만 대체 표시가 나오고 나머지 이미지·리스트는 정상 표시된다.

## Constraints

- 관광지·맛집 후보 데이터는 12번 태스크에서 확장한 `lib/nearby-places-data.ts`를 그대로 재사용한다.
- 이미지 4~5장은 후보 항목에 딸린 이미지(관광지·맛집 이미지)를 모아 구성하며, 이미지 전용 별도 데이터셋을 새로 만들지 않는다.

## Verification

- Day 카드가 해당 도시의 후보 리스트·이미지 개수(최대 5, 데이터가 적으면 그만큼)를 정확히 보여주는지 테스트.
- 같은 도시가 여러 Day에 걸쳐 나올 때 데이터 일관성 확인.
- 이미지 깨짐 시 해당 자리만 대체 표시되는지 확인.
