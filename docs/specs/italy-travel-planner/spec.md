# 이탈리아 여행 가이드 웹페이지

## 개요

여행을 떠나기 전, 한 페이지에서 이탈리아 여행 일정을 짜고 필요한 예약(항공·숙소) 사이트로 바로 연결해 준비를 한 번에 끝낼 수 있게 하는 웹 서비스. 웹에서 먼저 만들고, 이후 동일한 화면/기능을 앱으로도 이식할 예정이다.

## 사용자에게 보이는 결과

1. 도착·출발 항공 일정을 입력하면 이탈리아 주요 도시들을 효율적으로 도는 추천 루트를 받는다.
2. 꼭 가고 싶은 지역을 고르면, 그 지역들을 포함하면서도 이동이 최적화된 루트와 함께 각 구간의 이동수단·숙소 예약 검색 링크를 받는다.
3. 확정한 루트를 일자별(Day 1, Day 2...) 일정표로 보고, 캘린더 파일(.ics)이나 PDF로 내보낼 수 있다.
4. 위치 정보를 허용하면 현재 위치와 가장 가까운 큐레이션 도시의 맛집·관광지 목록과 사진을 볼 수 있다.
5. 여행 준비 체크리스트(여권 유효기간, 유심/이심, EU 입국 규정, 필수 짐 등)를 확인하고 항목을 체크할 수 있다.
6. 이동·숙소·식비 등 카테고리별 예상 비용을 직접 입력해 예산 합계를 확인할 수 있다.
7. 완성한 일정을 링크 하나로 다른 사람과 공유할 수 있다.
8. 짜던 일정은 브라우저에 자동 저장되어, 같은 기기·브라우저로 다시 방문해도 이어서 편집할 수 있다.
9. 도착·출발 도시와 일시는 로마 왕복(2027-05-23 19:00 도착 / 2027-05-30 21:00 출발) 기본값이 미리 채워진 채로 화면을 시작하고, 자유롭게 수정할 수 있다.
10. 꼭 가고 싶은 지역을 이탈리아 지도 위 도시 마커로 보고, 마커를 클릭·터치하면 그 도시의 대표 이미지 몇 장과 간단한 설명이 팝업으로 뜨며, 동시에 그 지역이 "꼭 가고 싶은 지역" 선택에 토글된다.
11. 확정된 추천 루트의 방문 순서를 같은 지도 위에 경로로 겹쳐 볼 수 있다.
12. 내 위치 주변 정보에서 맛집·관광지 각각 여러 후보를 보고, 각 후보를 구글맵 검색 결과로 바로 연결하는 버튼을 쓸 수 있다.
13. 일자별 일정의 각 Day에 그 도시의 관광지·맛집 후보 리스트와 이미지 4~5장을 함께 볼 수 있다.

## 승인된 범위

- 여행 플래너
  - 기본: 도착 도시/시간, 출발 도시/시간(다른 도시여도 됨) 입력 → 큐레이션 데이터 기반 추천 루트 제안. 첫 진입 시 로마 왕복(도착 2027-05-23 19:00, 출발 2027-05-30 21:00) 기본값이 채워져 있으며 계속 수정 가능하다.
  - 심화: 꼭 가고 싶은 지역(큐레이션 목록 중 다중 선택) 지정 → 해당 지역을 모두 포함하는 최적 루트 제안. 선택은 기존 체크박스 목록과 이탈리아 지도 위 도시 마커 클릭·터치 두 방법으로 모두 가능하며 같은 선택 상태를 공유한다.
  - 지도 위 도시 마커를 클릭·터치하면 그 도시의 대표 이미지 몇 장과 간단한 설명이 담긴 정보 팝업이 뜬다(선택 토글과 별개로 항상 뜬다).
  - 확정된 추천 루트의 방문 순서를 지도 위에 경로(선)로 시각화한다.
  - 확정된 루트의 각 구간에 대해 이동수단 검색 링크(예: Skyscanner, 기차 예매 사이트)와 숙소 검색 링크(예: Booking.com)를 도시·날짜가 채워진 형태로 제공.
  - 일자별 일정 뷰와 캘린더(.ics)/PDF 내보내기. 각 Day 카드에는 그 도시의 관광지·맛집 후보 리스트(구글맵 링크 포함)와 이미지 4~5장이 함께 표시된다.
- 내 위치 주변 정보: GPS 권한 허용 시 가장 가까운 큐레이션 도시를 판별해 그 도시의 맛집·관광지 후보 여러 개(항목별 이미지 포함)를 보여주고, 각 후보에는 구글맵 검색 결과로 연결되는 버튼이 붙는다.
- 여행 준비 체크리스트(정적 항목 목록 + 체크 상태 저장).
- 예산 트래커(카테고리별 예상 비용 입력 및 합계 표시, 실제 결제·연동 없음).
- 일정 공유 링크(현재 일정 상태를 담은 URL 생성).
- 일정 데이터는 브라우저 localStorage에 저장(로그인 없음).
- 전체 화면의 시각 디자인(제목/헤더, 카드 레이아웃, 색상·타이포·여백 등)을 학습용 데모 수준을 넘는 완성도로 다듬는다. 기능 변경 없이 룩앤필만 개선하는 범위다.

## 관찰 가능한 수용 기준

- 도착 도시/시간과 출발 도시/시간만 입력하고 꼭 가고 싶은 지역을 고르지 않아도, 도착 도시에서 시작해 출발 도시에서 끝나는 추천 루트가 생성된다. 이때 포함되는 중간 도시는 큐레이션 데이터의 "대표성" 기준(주요도가 높은 도시 우선)과 체류 가능 일수에 따라 정해진다.
- 꼭 가고 싶은 지역을 하나 이상 고르면, 추천 루트는 그 지역들을 모두 포함하면서 총 이동 시간이 합리적으로 짧은 순서로 배열된다.
- 큐레이션 목록에 없는 도시/지역은 "꼭 가고 싶은 지역" 선택 목록에 나타나지 않는다.
- 확정된 루트의 각 구간마다 이동수단 검색 링크와 숙소 검색 링크가 최소 하나씩 표시된다. 숙소 링크는 목적지·체크인/체크아웃 날짜가 채워진 외부 사이트(Booking.com) 검색 결과 페이지로 새 탭에서 열린다. 이동수단 링크는 실제 예매 사이트(Trenitalia)가 도시·날짜를 URL로 받는 방법을 제공하지 않아, 홈페이지로 새 탭에서 연결되고 구간의 도시·날짜는 우리 화면에 텍스트로 표시된다 — 근거는 [data-and-booking-strategy](../../decisions/data-and-booking-strategy.md) 참고.
- 위치 권한을 허용했을 때: 현재 GPS가 큐레이션 도시 중 하나와 충분히 가까우면 그 도시의 맛집·관광지 목록과 이미지가 표시된다. GPS가 이탈리아 큐레이션 도시들과 멀리 떨어져 있으면(예: 여행 전 한국에서 접속), 근처 도시 목록 대신 현재 짜고 있는 일정의 도착 도시(또는 사용자가 직접 고른 도시) 기준으로 목록을 보여준다.
- 위치 권한을 거부하거나 위치 조회에 실패해도, 도시를 직접 선택해 같은 맛집·관광지 목록 화면을 볼 수 있다.
- 맛집·관광지 항목에 연결된 이미지가 깨지면 항목 자체는 계속 보이고, 이미지 자리에는 대체 표시가 나온다.
- 일자별 일정 뷰에서 "내보내기"를 누르면 .ics 또는 PDF 파일이 생성된다.
- 체크리스트 항목을 체크하면 같은 브라우저로 다시 방문했을 때도 체크 상태가 유지된다.
- 예산 트래커에 카테고리별 금액을 입력하면 합계가 즉시 갱신되고, 새로고침 후에도 값이 유지된다.
- "공유 링크 만들기"를 누르면 URL이 생성되고, 그 URL을 다른 브라우저(로그인 없이)에서 열면 같은 루트/일정을 볼 수 있다.
- 브라우저를 닫고 같은 기기·브라우저로 다시 열면, 이전에 입력하던 일정(날짜, 선택 지역, 체크리스트, 예산)이 그대로 남아 있다.
- 화면을 처음 열면(저장된 일정이 없을 때) 도착 도시·출발 도시가 모두 로마로, 도착 일시가 2027-05-23 19:00, 출발 일시가 2027-05-30 21:00으로 채워져 있다. 이 값들은 다른 도시/일시로 자유롭게 바꿀 수 있다.
- 이탈리아 지도 위 도시 마커를 클릭·터치하면 그 도시의 대표 이미지 몇 장과 간단한 설명이 팝업으로 뜨고, 동시에 그 도시가 "꼭 가고 싶은 지역" 체크박스 목록에서도 선택/해제된다. 체크박스에서 선택/해제해도 지도 마커 표시가 같이 바뀐다.
- 큐레이션 목록에 없는 지역은 지도 위에 클릭 가능한 마커로 나타나지 않는다.
- 추천 루트가 만들어지면, 지도 위에 그 루트의 방문 순서를 나타내는 경로가 함께 표시된다.
- 내 위치 주변 정보 화면에서 맛집·관광지 각각 최소 2개 이상의 후보가 표시되고(큐레이션된 도시 데이터 범위 안에서), 각 후보에는 구글맵 검색 결과 페이지로 새 탭에서 연결되는 버튼이 있다.
- 일자별 일정의 각 Day 카드에 그 도시의 관광지·맛집 후보 리스트(구글맵 링크 포함)와 이미지 4~5장이 표시된다. 이미지가 4~5장보다 적게 큐레이션된 도시는 있는 만큼만 표시된다.

## 설정된 제약과 이유

- 웹 우선 개발, 이후 앱으로 이식 예정 — 사용자가 명시한 전체 방향. 이번 스펙은 웹 화면의 동작을 정의하며, 앱 이식은 이후 별도로 다룬다.
- 이동 데이터, 주변 정보, 예약 연동은 외부 API 없이 큐레이션 정적 데이터 + 딥링크 방식으로 한다 — 근거와 대안은 [data-and-booking-strategy](../../decisions/data-and-booking-strategy.md) 결정 기록 참고.
- 실제 예약/결제는 이 서비스에서 처리하지 않는다 — 위 결정과 동일한 이유이며, 결제 대행에 필요한 제휴·보안 준수 부담을 피하기 위함.
- 일정 데이터는 로그인 계정 없이 브라우저 localStorage에만 저장한다 — 계정/인증/DB 없이 학습용 템플릿 범위 안에서 바로 구현 가능하기 때문. 기기/브라우저를 바꾸거나 캐시를 지우면 데이터가 사라진다.

## 가정

- 큐레이션 도시/지역은 로마·밀란·베네치아·피렌체·볼로냐·나폴리 등 20~30곳 규모로 준비하며, 정확한 목록과 도시 쌍별 이동 시간 데이터는 구현 시점에 확정한다. (완료: 2026-08-20에 10개 도시로 시작해 이후 사용자 요청으로 돌로미티(코르티나 담페초)·아말피 해안 2곳을 추가해 12곳으로 확장. 필요 시 계속 추가 가능.)
- 맛집·관광지 이미지는 Unsplash, Wikimedia Commons 등 무료/오픈 라이선스 이미지를 사용한다. 이 항목은 질문이 한 차례 깨진 상태로 전달되어 사용자가 추천안을 확인하지 못했으므로, 가정으로 남기고 사용자가 다시 확인할 수 있게 한다.
- "효율적인 루트"는 총 이동 시간을 최소화하면서 체류 일수에 맞는 도시 수를 포함하는 것으로 해석한다. 여러 대안 루트를 제시하지 않고 하나의 추천 루트만 보여준다.
- 일정 공유 링크는 별도 백엔드 없이 일정 데이터를 URL에 인코딩하는 방식으로 구현한다. 일정이 커지면 URL이 길어질 수 있다(아래 리스크 참고).
- 체크리스트 항목(여권 유효기간, 유심/이심, EU 입국 규정 등)의 정확한 문구와 최신 규정은 구현 시점에 별도로 확인한다. (완료: 2026-08-20에 확인한 내용으로 작성. ETIAS 시행일은 EU가 아직 공식 발표하지 않아 "확인 필요"로만 안내한다.)
- 예산 트래커의 통화는 원(KRW)으로 가정한다. 화면 전체가 한국어 사용자를 대상으로 하기 때문이다.
- 이탈리아 지도는 실시간 지도 API(예: Google Maps, Leaflet+OSM 타일)를 불러오지 않고, `lib/travel-data.ts`의 큐레이션 좌표(lat/lng)를 화면 비율로 환산해 그리는 정적 SVG(또는 이에 준하는 좌표 기반 벡터)로 구현한다. 아래 범위 밖 항목(실시간 지도 API 연동)과 충돌하지 않는다.
- 도시별 대표 이미지·설명(지도 팝업용), 관광지·맛집 후보(내 위치 주변 정보·일자별 일정 공용)는 기존 맛집·관광지 큐레이션 데이터와 같은 방식(무료/오픈 라이선스 이미지, 정적 데이터)으로 확장한다.
- 구글맵 연결 버튼은 실시간 장소 검색 API가 아니라 정적 검색 딥링크(`https://www.google.com/maps/search/?api=1&query=...`)를 쓴다 — 근거는 [data-and-booking-strategy](../../decisions/data-and-booking-strategy.md)의 딥링크 방식과 동일한 접근.

## 범위 밖

- 실시간 지도/경로 API, 실시간 장소 검색 API 연동 — 위 결정 기록의 이유와 동일. (좌표 기반 정적 SVG 지도, 정적 구글맵 검색 딥링크는 실시간 API 호출이 아니므로 이 항목에 해당하지 않는다.)
- 실제 항공/숙소 예약 체결, 결제, 가격 실시간 비교 — 딥링크로 대체.
- 로그인 계정, 서버 DB, 여러 기기 간 동기화 — 이번 범위는 브라우저 로컬 저장까지만.
- 이탈리아 외 국가/도시 지원.
- 큐레이션 목록에 없는 소도시 지원.

## 보류

- 앱(모바일) 구현 — 사용자가 이후 별도로 진행할 예정.
- 다국어 지원 여부 — 언급되지 않아 보류.

## 남은 리스크

- (해결됨) 예약 사이트 딥링크 URL 형식을 실제로 확인한 결과, Booking.com은 ss/checkin/checkout 파라미터가 동작하지만 Trenitalia/Trainline 등 기차 예매 사이트는 도시·날짜만으로 만드는 딥링크가 없어 홈페이지 링크로 대체했다. 자세한 내용과 대안은 [data-and-booking-strategy](../../decisions/data-and-booking-strategy.md) 참고.
- 일정 공유 링크를 URL 인코딩 방식으로 구현할 경우, 체크리스트·예산 데이터까지 포함하면 URL이 브라우저/공유 플랫폼의 길이 제한을 넘을 수 있다. 필요 시 공유 범위를 루트/일정으로 좁히거나 별도 저장 방식을 재검토해야 한다.
- 큐레이션 정적 데이터(도시 목록, 이동 시간, 맛집/관광지, 체크리스트 문구)의 실제 값은 아직 준비되지 않았으며, 정확도는 준비 품질에 따라 달라진다.
- GPS가 이탈리아 큐레이션 도시들과 먼 경우의 대체 동작(도착 도시 기준 표시)이 실제로 사용자에게 충분히 이해되는지는 구현 후 확인이 필요하다.
